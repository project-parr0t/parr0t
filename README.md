> **개발 방식 공개:** Parr0t은 완전히 바이브 코딩으로 제작되었습니다. 개발자는 방향 제시와 사례 분석을 맡았고, 구현과 문서화는 코딩 에이전트를 중심으로 진행했습니다.

# Parr0t

게임의 전체 문맥을 분석하고, 번역·독립 검수·검증을 거쳐 복원 가능한 한국어 패치를 만드는 프레임워크입니다.
Codex에서 요청 프롬프트로 시작하거나, OMP에서 프롬프트·통신 격리 훅을 연결한 네이티브 에이전트로 실행할 수 있습니다.

## 사용법

1. [프롬프트 조합기](https://project-parr0t.github.io/parr0t/)에서 **한국어 패치 제작** 또는 **기존 프로젝트 업데이트·마이그레이션**을 선택합니다. 업데이트·마이그레이션에는 이전 레포지토리 URL을 입력합니다.
2. 생성된 프롬프트를 복사해 Codex 또는 아래 런처로 시작한 OMP 세션에 전달합니다. 패치 제작에는 **게임 폴더도 같은 메시지에 첨부**하거나 경로를 적고, 프로젝트 갱신에는 필요한 현재 게임 빌드를 추가합니다.
3. 외부 작업 폴더에 생성된 패치와 검증 결과를 확인합니다. 실제 게임에 설치하거나 실행하는 권한은 별도로 승인합니다.

한국어 패치 **존재 여부 검사만 생략**하거나 기존 한국어를 원어부터 재번역하는 요청을 구분할 수 있습니다. 폰트·UI 이미지·모드 제작, 역할별 모델·문맥 파악, 약/강검수 횟수와 전체/단계별 동시 실행 상한도 함께 조합할 수 있습니다.

검수 횟수·역할별 모델·폴백 경로는 명시한 사용자·템플릿 설정을 보존합니다. Sol이라는 모델명만으로 별도 상한을 두지 않습니다. 폴백 검수 횟수가 미지정이면 문서화된 기본값인 최초 호출 포함 **3회**를 사용하며, 모델·제공자는 승인된 정확한 바인딩만 사용합니다.

게임 파일과 추출문을 대화에 붙여 넣지 않아도 됩니다. 원본 게임은 읽기 전용으로 유지하며, 실제 처리 전에 Parr0t의 text-free control-plane 진입과 SDK 확인을 수행합니다. 게임 작업의 Git은 기본 비활성이고 명시적으로 승인한 경우만 활성화합니다. 대상 언어를 초기화·선택하면 그 선택 자체가 언어 정책에 기록됩니다. 제공자 정책과 기존의 명시적 제한도 보존합니다.

조합기의 로컬 실행과 GitHub Pages 게시 설정은 [시작 안내](manual/starting_prompts.md)에 정리했습니다. Pages 게시 주소는 위 링크이며, 첫 게시에는 저장소의 Pages 소스 설정이 필요합니다.

## OMP에서 사용하기

Python 3.11 이상과 OMP가 설치되어 있어야 합니다. 전체 코어 저장소를 내려받고 아래처럼 **게임 폴더를 열지 않은 상태에서 외부 작업 폴더부터** 초기화합니다.

일반 OMP 세션에서도 `parr0t_process`가 필요하면 OMP 사용자 확장 경로
`~/.omp/agent/extensions/parr0t-native-process.ts`에 아래 한 줄을 두어 현재 코어의
네이티브 실행 도구를 자동으로 등록합니다. 파일 URL은 실제 코어 위치로 바꿉니다.
OMP의 자동 탐색은 `.ts`/`.js` 진입 파일을 대상으로 하므로 이 파일을 `.mjs`로 만들지 않습니다.

```javascript
export { default } from "file:///C:/path/to/parr0t/src/game_l10n/templates/omp-native-process.mjs";
```

이 확장은 일반 세션과 그 하위 세션에 실행 도구만 제공하며, 게임 파일을 열거나
모델·권한·통신 정책을 변경하지 않습니다. 전용 도우미나 실행 가드가 이미 등록되어
있으면 덮어쓰지 않습니다. 도구 존재만으로 워커 격리나 제어 세션 ready가 증명되지는
않으므로 실제 게임 작업은 아래 정식 런처를 사용합니다. 이미 실행 중인 OMP는 확장을
다시 불러오거나 새 세션으로 시작해야 합니다.

외부 작업 초기화와 정식 제어 세션 실행:

```text
python -m pip install -e .
game-l10n init-workspace "<external-workspace>" --sdk-root "<repository>" --game-root "<source-root>"
python -m game_l10n.omp_session --workspace "<external-workspace>" --model "<approved-provider/model-id>" --mode workspace --foreground
```

`--model`에는 현재 OMP에서 허용된 정확한 최상위 모델 ID를 지정합니다. 새 세션에 위의 게임별 요청을 전달하세요. 기본 `prompt` 모드는 하위 에이전트의 충돌하는 협업 지시와 직접 메시지·기록 열람 경로를 제한하는 경량 훅을 연결하며, 일반 Python 실행은 유지합니다. 도구 등록은 새 세션에 적용되며 기존 세션에 도구를 추가하지 않습니다. 분리 실행의 `helper_registered`와 실제 PID·세션 ID로 등록을 확인하고, `startup_pending`이면 중복 실행하지 않습니다. 전체 실행 가드·전용 실행기가 필요하면 `--guarded`를 선택합니다. 어느 모드도 OS 샌드박스는 아닙니다. Codex의 기본 제공자 설정이나 전역 OMP 설정은 변경하지 않습니다. 이미 초기화된 작업은 첫 두 명령을 반복하지 않습니다.

명령만 확인하려면 마지막 명령에 `--print-command`를 추가합니다. 이 옵션은 세션이나 파일을 만들지 않습니다. 실제 게임 내용·비공개 기록에 노출된 제어 세션은 정식 handoff와 새 세션이 필요하며 `--mode rotation`을 사용합니다. 노출 없이 일시정지·분석·종료한 경우에는 현재 사용자의 명시적 재개 요청을 루트 `parr0t_framework_mode` 도구에 전달하여 같은 깨끗한 세션에서 재개할 수 있습니다. 별도 UI 확인은 필수가 아니며 이전 기록을 불러오는 `omp --resume`와도 다릅니다. 워커 모델 바인딩과 호스트 조건은 [OMP 진입 규약](docs/control-plane-contract.md#omp-entry)을 따릅니다.

Parr0t의 이전 버전 호환성은 **체크포인트 데이터로만** 보장합니다. 구형 런타임·경로·실행 규약을 유지하거나 복원하지 않습니다. 종료가 확인된 실행의 증거와 완료 결과를 보존한 뒤, 현재 Core·SDK와 검증된 체크포인트·저장소 데이터로 새 작업 및 실행 argv를 생성합니다. SDK 참조 이력도 Git 객체로 검증하며 과거 런타임 체크아웃에 의존하지 않습니다.

## 하는 일

- 전체 게임 흐름과 화면 구조를 먼저 분석하고, 대사가 있다면 장면·인물 관계·캐릭터별 말투까지 반영합니다.
- 문장 단위 번역 실패가 전체 작업을 중단하지 않도록 폴백합니다.
- 대사는 자연스러움·말투·패러디를, UI는 기능·용어·수치·단위의 일관성을 독립 검수합니다.
- 기존 한국어를 개선할 때는 원어를 뜻의 기준으로 삼고 항목 대응과 누락·오역을 다시 확인합니다.
- 플레이스홀더, 태그, 제어 코드, UI 배치와 게임 로직이 손상되지 않았는지 확인합니다.
- 원본을 수정하지 않고 새 패치와 복원 가능한 설치본을 만듭니다.
- 복구 가능한 실패는 최초 요청 범위에서 자동으로 이어가고 성공한 대상은 잠급니다. 독립적으로 완료된 묶음은 다른 대상의 실패를 기다리지 않습니다. 실제 사용자 중단·범위 변경·새 외부 권한은 그대로 존중합니다.
- 독립 인벤토리를 사용하지 않는 명시적 설정은 primary-only 보장이지 독립·전체 정적 검증이 아닙니다. 불완전 산출물은 별도 승인과 정직한 표시가 필요하며 무결성이 깨진 후보를 포함하지 않습니다. 로컬 패키지는 검증된 최소 무결성 체크포인트를 사용할 수 있지만 게시는 전체 배포 규약을 따릅니다.

## 데이터와 SDK

게임 파일, 추출문, 번역문, 로그와 API 키는 Parr0t 저장소에 넣지 않습니다. 게임별 데이터는 각 호스트의 외부 작업 폴더에만 남습니다.

`main`은 엔진 중립 오케스트레이션 코어이며, 실제 게임 형식은 `sdk-<engine>-<version>` 브랜치가 담당합니다. 새 도구를 만들기 전에 기존 SDK를 확인하고, 성공이 검증된 재사용 코드만 게임 데이터를 제거한 뒤 SDK로 승격합니다.
