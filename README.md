> **개발 방식 공개:** Parr0t은 완전히 바이브 코딩으로 제작되었습니다. 일반 개발자는 방향 제시와 사례 분석을 맡았고, 구현과 문서화는 코딩 에이전트를 중심으로 진행했습니다.

# Parr0t

게임의 문맥을 읽고, 번역을 끝까지 라우팅하며, 되돌릴 수 있는 패치를 만드는 **Codex용 게임 현지화 프레임워크**입니다.

[정식 저장소 주소](https://github.com/project-parr0t/parr0t) · [MIT License](LICENSE)

Parr0t은 번역기 하나를 호출하는 스크립트가 아닙니다. 게임의 전체 흐름과 캐릭터 말투를 먼저 분석하고, 번역과 독립 검수, 실패 항목의 폴백, 파일 형식 검증, 패치 제작까지 하나의 작업으로 관리합니다.

사람이 명령어를 하나씩 실행하는 일반 프로그램도 아닙니다. 사용자는 목표와 경계를 정하고, **Codex가 이 저장소의 규칙과 대상 게임을 읽어 작업을 수행**합니다. OpenCodex 같은 호환 라우팅 계층도 사용할 수 있지만, 기본 실행 환경은 Codex입니다.

## 무엇이 다른가요?

- **문맥부터 분석합니다.** 대사 한 줄만 보지 않고 장면 순서, 인물 관계, 성격, 존댓말과 반말, 고유명사를 함께 봅니다.
- **직역만 맞는 번역으로 처리하지 않습니다.** 의미뿐 아니라 말투, 분위기, 패러디와 말장난, 제목과 퀘스트명의 리듬도 검수합니다.
- **한 문장의 실패가 전체 작업을 멈추지 않습니다.** 번역 또는 검수가 거부되거나 실패하면 해당 항목만 격리해 다음 경로로 보냅니다.
- **기존 SDK를 먼저 재사용합니다.** 새 언패커나 패처를 만들기 전에 호환 가능한 `sdk-*` 브랜치를 조사하고, 완전 호환이면 재사용하고 부분 호환이면 필요한 부분만 확장합니다.
- **게임 원본과 작업 데이터를 분리합니다.** 원본 게임 폴더는 읽기 전용으로 다루고, 추출 데이터·번역문·로그·패치는 별도 작업공간에 둡니다.
- **설치와 실행을 멋대로 하지 않습니다.** 패치 제작, 실제 설치, 게임 실행, 공개 배포는 서로 다른 작업으로 취급하며 필요한 시점에 각각 확인합니다.

```text
게임과 요청 확인
  → 기존 한국어 및 재사용 가능한 SDK 확인
  → 읽기 전용 추출
  → 전체 흐름·캐릭터·용어 분석
  → 번역
  → 실패 항목만 폴백
  → 독립 검수와 선택적 수정
  → 형식·스크립트·용어 무결성 검사
  → 새 패치와 복원 가능한 설치본 제작
```

## 시작하기

### 준비할 것

- [Codex App 또는 Codex CLI](https://github.com/openai/codex)
- Parr0t 저장소
- 번역할 게임의 설치 폴더 또는 언팩된 데이터
- 게임 데이터와 분리된 쓰기 가능한 작업 폴더
- 선택한 외부 번역 경로가 요구하는 API 키(선택 사항)

비공개 저장소를 사용한다면 브라우저 로그인이 아니라 **Codex가 실행되는 환경의 로컬 Git 자격 증명**으로 접근할 수 있어야 합니다. 토큰을 프롬프트에 붙여 넣거나 저장소에 기록하지 마세요.

### Codex에서 실행하기

1. Parr0t 저장소와 대상 게임 폴더를 같은 Codex 프로젝트 범위에서 엽니다.
2. 게임 밖에 별도 작업 폴더를 하나 지정합니다.
3. 아래 요청문의 대괄호 부분만 상황에 맞게 바꿔 Codex에 보냅니다.
4. Codex가 요구하는 Git 사용 여부, 실제 설치·실행 여부, 최종 공개 여부만 사람이 결정합니다.

## 상황에 맞게 프롬프트 바꾸기

위 프롬프트를 매번 길게 다시 쓰기보다, 기본 요청 뒤에 필요한 조건만 추가하는 편이 좋습니다.

### 비공개 Parr0t 저장소를 사용할 때

```text
Parr0t 저장소는 비공개다. Codex 실행 환경에 설정된 로컬 Git 자격 증명으로 접근하고, 인증 정보를 출력하거나 파일에 저장하지 마라. 접근할 수 없으면 새 구현을 시작하지 말고 인증 문제만 보고하라.
```

### 폴백 API 키를 나중에 제공할 때

```text
기본 번역 경로에서 처리 가능한 항목을 먼저 모두 완료하라. 거부되거나 실패한 항목은 별도 대기열에 보존하고, [DeepSeek 또는 다른 공급자] 키가 실제로 필요해진 시점에 한 번만 요청하라. 키가 제공되면 미완료 항목만 재개하라.
```

API 키는 환경 변수로만 전달합니다. 특정 공급자 조합은 권장 구성일 뿐이며, Parr0t의 핵심 파이프라인은 번역·검수·재작성 역할별로 다른 공급자를 사용할 수 있습니다.

### 게임에 맞는 한글 폰트가 필요할 때

```text
한글 글리프 지원, 게임의 렌더링 방식과 기술적 제약, 화면 분위기, 가독성, 배포 라이선스를 함께 확인해 폰트를 선택하라. 기존 폰트를 교체할 필요가 없다면 교체하지 말고, 포함하는 폰트의 출처와 라이선스를 배포본에 남겨라.
```

### Steam 게임일 때

```text
정확한 Steam App ID와 설치 매니페스트로 게임 폴더를 확인하라. Steam 업데이트나 무결성 검사를 막거나 우회하지 말고, 검사 후 Steam 관리 파일이 복원될 수 있음을 전제로 패치 상태 확인·재설치·복원을 제공하라. Steam 설정 파일과 시작 옵션은 수정하지 말고 Steam을 종료하지 마라.
```

Steam 무결성 검사로 관리 파일이 원래 상태로 돌아가는 것을 패치가 영구적으로 막을 수는 없습니다. Parr0t은 플랫폼 동작을 방해하는 대신, 패치 소유 파일과 상태를 검증하고 사용자가 안전하게 다시 적용하거나 복원할 수 있게 만드는 방식을 사용합니다.

### 결과물만 받고 싶을 때

```text
설치 가능한 패치까지만 제작하라. 실제 설치, 게임 실행, 저장 데이터 수정, 공개 저장소 생성과 Release 업로드는 하지 마라.
```

### 완성된 패치를 공개할 때

```text
내가 성공을 확인한 뒤에만 공개 절차를 시작하라. 실행자의 환경을 기준으로 배포하고, 별도 지시가 없으면 Windows를 대상으로 하라. 지원 게임 버전, 소스 커밋, 태그, Release, 매니페스트와 배포 파일의 버전·해시가 모두 일치하도록 한 번 빌드한 검증본만 게시하라.
```

## 결과물은 어디에 남나요?

게임별 데이터는 Parr0t 저장소가 아니라 지정한 외부 작업 폴더에 남습니다.

```text
Parr0t 저장소
  └─ 오케스트레이션 코어, 문서, 재사용 가능한 SDK만 보관

외부 작업 폴더
  ├─ 추출 데이터와 전체 문맥 분석
  ├─ 용어집과 캐릭터 말투
  ├─ 번역·검수 상태와 비공개 로그
  └─ 패치 및 설치 패키지
```

성공이 확인된 언팩·팩·적용 도구만 게임 데이터를 완전히 제거한 뒤 `sdk-<engine>-<version>` 브랜치로 승격할 수 있습니다. 성공 확인과 SDK 공개 승인은 별도입니다.

## 알아둘 점

- `main`은 엔진 중립 오케스트레이션 코어입니다. 실제 게임 형식을 다루려면 호환 SDK 브랜치 또는 비공개 어댑터가 필요합니다.
- Parr0t은 게임 원본 파일, 번역 데이터, API 키를 포함하지 않습니다.
- 모델 또는 API 공급자의 안전장치를 비활성화하거나 우회한다고 주장하지 않습니다. 정상적인 번역이 거부되면 항목 단위로 격리해 허용된 다른 경로로 라우팅합니다.
- DRM, 안티치트, 구매 제한 또는 플랫폼 보호 기능을 우회하는 도구가 아닙니다.
- 실제 설치와 실행은 기본적으로 사용자가 수행합니다. 에이전트에게 맡길 때도 각각 별도 확인이 필요합니다.
