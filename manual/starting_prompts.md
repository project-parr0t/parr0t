# 시작 프롬프트 조합기

[조합기 열기](https://project-parr0t.github.io/parr0t/) · [README](../README.md)

## 사용

게임 유형과 필요한 조건을 선택하고 생성된 프롬프트를 복사하세요. Codex에는 게임 내용을 아직 읽지 않은 세션에, OMP에는 [README의 공식 런처](../README.md#omp에서-사용하기)로 시작한 새 세션에 게임 폴더 경로와 함께 전달합니다. 런처의 기본 `prompt` 모드는 하위 에이전트 통신 제한 훅과 네이티브 프로세스 도구 `parr0t_process`를 연결합니다. 전체 실행 가드·`parr0t_exec`·OS 샌드박스를 제공한다는 뜻은 아닙니다. 이미 실행 중인 일반 세션에 프롬프트를 붙이는 것만으로 훅이나 도구가 등록되지는 않습니다. 게임 대사나 추출문을 대화에 붙여 넣지 마세요.

런처가 분리 실행에서 `helper_registered`를 반환하면 기록된 PID·세션 ID의 **새 세션**을 사용합니다. `startup_pending`은 등록 확인 대기이며 성공도 재실행 지시도 아닙니다. 기존 세션의 도구 목록이 그대로인 것은 새 세션의 등록 실패가 아닙니다. 작업 폴더의 text-free `ready`와 실행 도구의 준비 상태도 별개입니다.

전체 실행 가드·전용 실행기와 호스트 격리 증명이 필요하면 `omp_session --guarded`로 가드를 연결하고 `native-runtime --host omp --omp-isolation guarded`로 바인딩합니다. 이 모드에서는 확장 프로그램과 `parr0t_exec` 및 실제 가드 증명이 계속 필요합니다. 새 OMP 런타임은 실제 가드 환경이 없으면 `prompt`가 기본이며, 기존 가드 바인딩은 명시적으로 변경하기 전까지 엄격하게 유지됩니다. 모드를 바꿔도 이미 시작한 불변 워커의 바인딩은 다시 붙이지 않습니다. 정확한 모델 권한·중첩 디스패치·제공자 preset·소스 읽기 제한은 어느 모드에서나 그대로입니다. 오염된 세션이나 분석 종료 후의 번역 재개에는 기존 정식 복구 규약이 적용됩니다.

한국어 패치 존재 여부 검사 생략, 기존 한국어 재번역, 게임에 맞는 폰트 설정, 모드 형태 제작을 한 요청으로 조합할 수 있습니다. **검사 생략은 한국어 번역·검수 생략이 아닙니다.** 재번역은 기존 한국어가 있다는 이유로 중단하지 않고 원어부터 교체하는 요청입니다.

기존 프로젝트를 갱신하려면 작업을 **프로젝트 업데이트·마이그레이션**으로 바꾸고 **이전 레포지토리 URL**을 입력하세요. 해당 프로젝트의 설정·체크포인트·기존 변경·복원 정보를 보존하며 현재 Parr0t 규약으로 이행하는 요청을 생성합니다. 페이지가 URL에 접속하거나 레포지토리를 직접 변경하지는 않습니다.

## 모델·문맥·이미지

**모델·문맥**에서 기초 번역·약검수·강검수·문맥 파악 모델의 정확한 ID를 지정할 수 있습니다. 빈칸은 기존 preset 설정을 유지하며, 모델 ID를 입력했다고 해당 호스트의 지원·사용 권한이 생기는 것은 아닙니다.

조합기는 지정된 모든 모델 ID를 코어와 같은 문법으로 검사합니다. 백슬래시·내부 공백이 포함된 경로나 표시명, 예약 별칭은 프롬프트 생성 전에 오류로 표시하고 복사·저장을 막습니다. 이는 문법 검증이며 호스트의 모델 지원·권한 확인을 대신하지 않습니다. 이미 보존된 잘못된 요청을 다른 모델로 추측해 바꾸지는 않습니다.

문맥 파악을 끄면 새 문맥 모델을 호출하지 않고 유효한 기존 문맥만 재사용합니다. 문맥이 없으면 필수 게이트를 통과한 것으로 꾸미지 않고 필요한 입력이나 승인 경계를 보고합니다.

**UI 이미지 속 글자 번역**은 기본 꺼짐입니다. 켜면 별도 요청 정책을 기록한 뒤 확정된 플레이어 노출 UI 이미지 영역만 처리합니다. 전체 이미지 스캔·무차별 OCR은 요청에 포함하지 않습니다.

## 검수 설정

- Sol 검수는 최초 호출을 포함해 대상당 최대 2회이며, 성공한 대상은 다시 검수하지 않습니다.
- 폴백 검수는 정확한 모델과 양의 정수 횟수를 사용자가 지정합니다. 횟수는 추가 재시도 수가 아닌 최초 호출을 포함한 최대 호출 수입니다.
- 사전 템플릿·사용자 요청에 모델과 횟수가 이미 명시되어 있으면 그 값을 보존합니다. 기본값으로 덮어쓰거나 같은 값을 다시 묻지 않습니다.
- 폴백 설정을 비워 두면 생성 프롬프트는 폴백 사용 전에 누락된 값을 사용자에게 확인하도록 지시합니다. 설정 누락을 모델 거부·경로 소진이나 번역 대상 제외로 처리하지 않습니다.
- 모델 지정은 기존 제공자 역할·정확한 모델 바인딩·허용 경로를 우회하는 권한이 아닙니다.

**검수 제한**에서 최대 약검수·강검수 횟수와 전체·약검수·강검수별 최대 동시 실행 서브에이전트 수를 지정할 수 있습니다. 미지정 값은 기존 설정을 유지합니다. 실제 동시성은 전체 상한, 단계별 상한, 기존 호스트·모델 상한 중 작은 값입니다. 횟수 제한은 대상 수나 전체 커버리지를 줄이는 설정이 아닙니다.

## OpenCodex 모델 목록

폴백 목록은 기본적으로 GPT와 Claude로 구분되며 정확한 ID를 직접 입력할 수도 있습니다. Claude 기본 ID는 [공식 모델 목록](https://platform.claude.com/docs/en/models/overview)을 참고합니다. 목록에 보이는 것만으로 실제 모델 가용성이나 실행 권한을 보장하지 않습니다.

**localhost 연결 요청**을 켜면 브라우저가 `http://localhost:10100/v1/models`를 직접 조회합니다. 페이지 로드 시에는 연결하지 않습니다. 로컬호스트 접근이 허용되고 목록을 받으면 기본 GPT/Claude 그룹 대신 OpenCodex 모델을 표시합니다. 별도 연결 프로그램이나 설정·캐시 파일 조회는 필요 없습니다.

브라우저가 로컬 네트워크 접근 권한을 묻는 경우 해당 연결을 허용하세요. 이 권한은 CORS 허용을 대체하지 않습니다. 조회가 차단되거나 미확인 상태이면 기본 GPT/Claude 목록을 유지합니다. 토글을 꺼도 이미 지정한 모델 ID·횟수는 덮어쓰지 않습니다.

요청에는 API 키·쿠키·게임 경로·생성 프롬프트를 보내지 않습니다. 모델 목록을 받았다는 사실은 모델 생성 요청의 성공이나 실행 권한까지 보장하지 않으며, 제공자·전역 설정도 변경하지 않습니다.


## 로컬 실행

저장소 루트에서 다음 명령을 실행하고 `http://127.0.0.1:8000/`을 여세요. 파일을 직접 여는 대신 로컬 HTTP 서버를 사용합니다.

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory pages
```

입력값과 프롬프트 조합은 브라우저 안에서 처리합니다. 폴더 경로 입력은 경로 문자열만 사용하며 게임 파일을 읽거나 업로드하지 않습니다. 폴백 모델·횟수 지정도 제공자 설정을 변경하거나 실제 모델을 호출하지 않습니다.

## GitHub Pages 게시

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. `pages/`와 Pages 워크플로를 포함한 변경이 `main`에 반영되면 `.github/workflows/pages.yml`이 정적 페이지를 게시합니다. Actions에서 수동 실행할 수도 있습니다.

게시 대상은 `pages/`뿐입니다. 게임 데이터·작업 폴더·자격 증명은 포함하지 않습니다. 위 절차는 저장소 관리자의 게시 설정 안내이며, 문서나 로컬 서버 실행만으로 원격에 게시되지는 않습니다.
