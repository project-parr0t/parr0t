# 시작 프롬프트 조합기

[조합기 열기](https://project-parr0t.github.io/parr0t/) · [README](../README.md)

## 사용

**실행 호스트**에서 Codex 또는 OMP를 선택하세요. Codex는 기존처럼 프롬프트를 복사해 게임 내용을 아직 읽지 않은 세션에 게임 폴더 경로와 함께 전달합니다. OMP는 설명문 대신 **PowerShell 실행 명령**을 복사하며, PowerShell에 붙여 넣어 실행합니다. 저장하면 Codex는 `.txt`, OMP는 UTF-8 `.ps1` 파일입니다. 호스트를 바꿔도 입력한 경로와 모델 선택은 유지됩니다. 게임 대사나 추출문을 대화에 붙여 넣지 마세요.

OMP에는 설치된 OMP와 현재 공식 Parr0t Core 체크아웃이 필요합니다. **현재 Parr0t Core 폴더**에는 절대 경로를 입력하며, 비우면 `$HOME/parr0t`를 사용합니다. 명령은 Core가 없으면 모델을 시작하기 전에 실패하며 자동 clone·설치·게임 실행을 하지 않습니다. 게임 폴더가 아닌 별도 외부 제어 폴더에서 정확한 Core의 `omp-native-process.mjs`를 `--trusted-extension`으로 로드하고, 명시적 전체 부트스트랩의 첫 진입점인 `parr0t_session`을 통해 요청에 따른 공식 컨트롤러를 시작합니다. 전역 확장 등록이나 전역 설정 변경은 필요 없습니다.

명시한 역할·폴백 모델은 해당 실행의 제어 폴더에 둔 운영자 `--config`의 `modelRoles`로 전달합니다. 기존 전역 역할·기본 설정은 유지하며, 정확한 선택자를 다른 모델로 바꾸지 않습니다. 명령·요청·설정 파일은 이에 의존하는 컨트롤러가 종료될 때까지 보관하세요. 화면에 명령이 표시되거나 복사·저장된 것만으로 실행 또는 실제 모델 권한·가용성이 확인된 것은 아닙니다.

전체 부트스트랩 도구 등록은 통신 제한이나 OS 격리의 강제 증명이 아닙니다. 실제 가드·호스트 격리의 별도 요구와 모델 권한 경계는 그대로 적용됩니다. 이미 요청한 자동화에 추가 사람 확인을 요구하기 위한 단계가 아니며, 실제 게임 내용·비공개 기록에 노출되었다면 정식 handoff와 새 세션이 필요합니다. 자세한 호스트 실행 조건은 [README](../README.md#omp에서-사용하기)를 참고하세요.

한국어 패치 존재 여부 검사 생략, 기존 한국어 재번역, 게임에 맞는 폰트 설정, 모드 형태 제작을 한 요청으로 조합할 수 있습니다. **검사 생략은 한국어 번역·검수 생략이 아닙니다.** 재번역은 기존 한국어가 있다는 이유로 중단하지 않고 원어부터 교체하는 요청입니다.

기존 프로젝트를 갱신하려면 작업을 **프로젝트 업데이트·마이그레이션**으로 바꾸고 **이전 레포지토리 URL**을 입력하세요. 해당 프로젝트의 설정·체크포인트·기존 변경·복원 정보를 보존하며 현재 Parr0t 규약으로 이행하는 요청을 생성합니다. 페이지가 URL에 접속하거나 레포지토리를 직접 변경하지는 않습니다.

## 모델·문맥·이미지

**모델·문맥**에서 기초 번역·약검수·강검수·재작성·문맥 파악 모델의 정확한 ID를 지정할 수 있습니다. 빈칸은 기존 설정 또는 초기 preset 기본값을 유지합니다. Preset은 고정 모델·제공자 수나 불변 경로가 아닙니다. 명시적 모델 선택은 Parr0t 작업의 선택 기록이며 실제 호스트의 실행 권한·가용성은 별도입니다.

조합기는 제어 문자·파일 경로·와일드카드·예약 별칭을 거부하면서 호스트가 지원하는 정확한 선택자의 문장부호·유니코드를 보존합니다. OMP에서는 제공자·upstream·effort를 포함한 정확한 선택자를 사용합니다. Bare ID는 권위 있는 호스트 메타데이터의 정확한 일치가 하나일 때만 바인딩하며 접두사를 추측하지 않습니다. 목록에 있다는 사실은 권한 승인이 아니고, 문법 검증도 가용성 증명이 아닙니다. 이미 보존된 요청을 다른 모델로 추측해 바꾸지 않습니다.

문맥 파악을 끄면 새 문맥 모델을 호출하지 않고 유효한 기존 문맥만 재사용합니다. 문맥이 없으면 필수 게이트를 통과한 것으로 꾸미지 않고 필요한 입력이나 승인 경계를 보고합니다.

**UI 이미지 속 글자 번역**은 기본 꺼짐입니다. 켜면 별도 요청 정책과 검증된 로컬 자산 범위를 기록합니다. 명시적으로 요청한 플레이어 노출 이미지 범위는 비-UI CG·배경의 글자도 포함할 수 있습니다. 폰트·화면 확인에 필요한 제한된 시각 검사는 이미지 번역 승인과 별개이며, 텍스트 작업 전체 완료를 이미지 작업의 선행 조건으로 두지 않습니다. 검사하지 않은 요청 범위를 대상 없음으로 처리하거나 무차별 OCR로 넓히지 않습니다.

## 검수 설정

- 검수 상한은 사용자가 지정한 대상별 호출 횟수입니다. Sol이라는 모델명만으로 최대 2회를 강제하지 않으며, 기존 작업에 명시된 2회 제한은 그대로 보존합니다. 성공한 대상은 다시 검수하지 않습니다.
- 폴백 검수는 승인된 정확한 모델 바인딩을 사용합니다. 횟수는 추가 재시도 수가 아닌 최초 호출을 포함한 최대 호출 수입니다.
- 사전 템플릿·사용자 요청에 모델과 횟수가 이미 명시되어 있으면 그 값을 보존합니다. 기본값으로 덮어쓰거나 같은 값을 다시 묻지 않습니다.
- 폴백 횟수가 미지정이면 문서화된 preset 기본값 3회를 기록합니다. 누락된 모델 권한을 만들어 내거나 설정 누락을 경로 소진·번역 대상 제외로 처리하지 않습니다.
- 역할·제공자 경로는 명시적으로 변경할 수 있지만 실제 호스트 권한·전송 및 자격 증명 범위를 우회하지 않습니다. 이미 시작한 불변 바인딩은 변경하지 않습니다.

**검수 제한**에서 최대 약검수·강검수 횟수와 전체·단계별 최대 동시 실행 서브에이전트 수를 지정할 수 있습니다. 미지정 값은 기존 설정을 유지합니다. 실제 동시성은 명시적 제한과 호스트·모델의 실제 용량에 맞추며 자동 분할·backpressure를 사용합니다. 임의의 고정 개수 제한이나 전체 작업 예산을 추가하지 않습니다. 횟수 제한은 대상 수나 전체 커버리지를 줄이는 설정이 아닙니다. 시간·토큰·비용 예산은 각각 선택 사항이며 미측정 사용량은 미확인으로 남습니다.

## OpenCodex 모델 목록

폴백 목록은 기본적으로 GPT와 Claude로 구분되며 정확한 ID를 직접 입력할 수도 있습니다. Claude 기본 ID는 [공식 모델 목록](https://platform.claude.com/docs/en/models/overview)을 참고합니다. 목록에 보이는 것만으로 실제 모델 가용성이나 실행 권한을 보장하지 않습니다.

**localhost 연결 요청**을 켜면 브라우저가 `http://localhost:10100/v1/models`를 직접 조회합니다. 페이지 로드 시에는 연결하지 않습니다. 로컬호스트 접근이 허용되고 목록을 받으면 기본 GPT/Claude 그룹 대신 OpenCodex 모델을 표시합니다. 별도 연결 프로그램이나 설정·캐시 파일 조회는 필요 없습니다.

브라우저가 로컬 네트워크 접근 권한을 묻는 경우 해당 연결을 허용하세요. 이 권한은 CORS 허용을 대체하지 않습니다. 조회가 차단되거나 미확인 상태이면 기본 GPT/Claude 목록을 유지합니다. 토글을 꺼도 이미 지정한 모델 ID·횟수는 덮어쓰지 않습니다.

요청에는 API 키·쿠키·게임 경로·생성 프롬프트를 보내지 않습니다. 모델 목록을 받았다는 사실은 모델 생성 요청의 성공이나 실행 권한까지 보장하지 않으며, 제공자·전역 설정도 변경하지 않습니다.


## 로컬 실행

저장소 루트에서 다음 명령을 실행하고 `http://127.0.0.1:8000/`을 여세요. 파일을 직접 여는 대신 로컬 HTTP 서버를 사용합니다.

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory pages
```

입력값과 프롬프트 조합은 브라우저 안에서 처리합니다. 폴더 경로 입력은 경로 문자열만 사용하며 게임 파일을 읽거나 업로드하지 않습니다. 폴백 모델·횟수 지정도 제공자 설정을 변경하거나 실제 모델을 호출하지 않습니다.

## GitHub Pages 게시

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. `pages/`와 Pages 워크플로를 포함한 변경이 `main`에 반영되면 `.github/workflows/pages.yml`이 정적 페이지를 게시합니다. Actions에서 수동 실행할 수도 있습니다.

게시 대상은 `pages/`뿐입니다. 게임 데이터·작업 폴더·자격 증명은 포함하지 않습니다. 위 절차는 저장소 관리자의 게시 설정 안내이며, 문서나 로컬 서버 실행만으로 원격에 게시되지는 않습니다.
